# Warpai 1.6.0

Warpai 1.6.0 adds native Windows WSL workspaces while retaining the collaboration
and provider usage improvements from 1.5.5. Companion remains 4.0.0 and protocol
major remains 1. No telemetry or bundled cloud AI is added.

## Changes from 1.5.5

- Windows terminals connected to WSL 2 use the confirmed Linux distribution,
  account and project for files, native editing, Markdown previews and Review.
  SSH workspaces retain their existing SFTP transfer path.
- Windows includes a dedicated WSL Companion payload with private Git. Install
  or remove it for the selected logged-in WSL account in Agent communication
  settings; its installation and service state stay separate from SSH Companion.
- Native guest Agents use their Linux MCP configuration and process identity.
  Communication settings, discovery and removal target the selected account,
  preserving Windows, SSH, other WSL accounts and unrelated MCP servers.
- Guest registration, task delivery and wake acknowledgement retain terminal,
  foreground process, account and project guards. Codex interactive participation
  uses its native --no-daemon option without wrapping the Agent.
- The macOS desktop retains the existing local and SSH workspace features.

## Downloads

- macOS 11.0 or newer, Apple silicon: `Warpai-1.6.0-macos-arm64.dmg`.
- Windows x64: `WarpaiSetup-1.6.0-windows-x64.exe`.
- Remote Linux x64: `WarpaiCompanion-4.0.0-linux-x64.run`.
- Remote macOS Apple silicon: `WarpaiCompanion-4.0.0-macos-arm64.dmg`.
- Remote Windows x64: `WarpaiCompanion-4.0.0-windows-x64-setup.exe`.

The Windows desktop installer includes the WSL guest payload. SHA-256 lists
cover all five public installers. macOS uses ad-hoc signing; Windows installers
are unsigned and may require first-launch approval.

## Verification

Source acceptance and native capture receipts are recorded in the
[WSL CI diagnosis](https://github.com/OthinusG/warpai/blob/v1.6.0/specs/wsl-1.6.0/CI-DIAGNOSIS.md).
Formal tagged installer/source/version/runtime gates run during release packaging.
Cloud acceptance uses owned disposable Agent fixtures and synthetic provider data,
without personal credentials or live vendor model requests.
