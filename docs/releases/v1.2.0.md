# Warpai 1.2.0

Warpai 1.2 turns the SSH Agent workspace introduced in 1.1 into a complete
remote working loop: coordinate Agents, inspect their files, edit and save,
preview the results and review changes in the same application.

## What changed from 1.1 to 1.2

### File tools now work in SSH projects

- Project Explorer follows the focused terminal's confirmed remote directory.
  Connect with SSH and use `cd`; the existing file tools follow along, including
  projects without Git. No separate file connection is needed.
- Browse, create, rename and delete remote files using the existing Explorer.
- Click remote code or text to open Warpai's existing editor, make changes and
  save them back to the original remote file.
- Open Markdown in the existing preview, including relative remote images and
  links. File names retain their remote identity across Windows and Unix paths.
- Open files keep their original remote connection when you switch terminals or
  directories. Conflicting saves and disconnects preserve unsaved edits;
  reconnect is explicit and does not silently repeat an uncertain write.

For example, connect to a research server, ask Agents to analyze data and draft
a report, then open the generated scripts and illustrated Markdown report in
Warpai. Review the results, make corrections and save on the server without
moving the project to a local IDE.

### Remote Git changes use the original Review workflow

- Inspect uncommitted remote changes and compare against available branches in
  the existing Git Review interface, with the original navigation and controls.
- Open reviewed remote files in the existing editor and send feedback to an
  eligible Agent terminal in the original SSH project.
- Switching projects or closing Review stops the old view's refresh work.
  A pending SSH connection does not display the previous local repository.
- Remote Git Review is read-only. Run commits, staging and other Git mutations
  in the remote terminal.

### Agent collaboration is easier to follow

- The daily collaboration view focuses on Agents, task descriptions, progress,
  conversations, submissions and review decisions.
- Participants use readable names. Long assignments remain readable in narrow
  layouts and at increased text sizes.
- Internal protocol identifiers, revision counters and maintenance bookkeeping
  are kept out of the daily view. History and maintenance remain available
  through their existing navigation.

### Agent setup and legacy cleanup improve

- Settings can remove Warpai communication MCP entries from supported installed
  Agents, including entries created under the former Warp/Warp Lite name.
- Cleanup preserves unrelated MCP servers and reports configurations that could
  not be safely cleaned. Re-enable the Agents you want to use afterward.
- Agent setup failures retain actionable error details instead of only a generic
  setup-failure message.
- Normal Codex communication retains its existing session behavior; the explicit
  cleanup action also handles old persistent Warpai entries.

### SSH file reliability improves

- Native SSH/SFTP file operations are verified on macOS and Windows, including
  controlled ProxyJump routes, save conflicts and reconnects.
- Remote file operations remain bound to the intended account, project and
  session; failed remote requests do not fall back to desktop files.
- Windows drive paths, Unicode names, directory aliases and temporary-file
  handling receive cross-platform fixes.

## Downloads and upgrading

- **macOS Apple silicon:** `Warpai.dmg`; move Warpai.app into Applications.
- **Windows x64:** `WarpaiSetup-x64.exe`.
- **Linux x64 SSH hosts:** `WarpaiCompanion-linux-x64.run`.
- **macOS Apple silicon SSH hosts:** `WarpaiCompanion-macos-arm64.dmg`.
- **Windows x64 SSH hosts:** `WarpaiCompanion-windows-x64-setup.exe`.

**Update the remote Companion from this release as well as the desktop app.**
An older 1.1 Companion does not provide the new file and Git Review capabilities.
The installers support repeat installation in the account's existing Warpai
location. Your CLI Agents continue to use their own providers and authentication.

All five installers are built from the immutable `v1.2.0` source tag. Companion
manifests record source, target and binary checksums; the release includes
SHA-256 files for downloads. Companion protocol/component versions remain
independent of the desktop product version.

macOS uses ad-hoc signing, not notarization. Approve first launch in System
Settings > Privacy & Security if required after checking the download source.
Windows may request approval for an unsigned installer.

## Verification

Before packaging, both desktop targets passed default and `warp_platform`
builds, focused application tests and the complete native remote-file and Agent
walkthrough. Each desktop walkthrough produced 169 nonempty screenshots;
selected file, preview, Review and narrow collaboration layouts were inspected.
The Companion backend and controlled SSH checks passed on Linux, macOS and
Windows. Formal package jobs additionally verify native installation, version,
source manifests, checksums, icons and bundled components before publication.
