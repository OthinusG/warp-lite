# Warpai 1.0.1

The first release under the **Warpai** name: a native, local-first terminal
workspace for commands, projects and independently installed CLI agents.

## In this release

- GPU-rendered terminal with command blocks, tabs and split panes.
- Project Explorer, source editor, Vim mode and Markdown viewing.
- Local agent messages, task delegation, evidence submission and review.
- Automatic session-only Codex MCP for ordinary interactive, permission-flag
  and resume launches, with an isolated native backend per terminal.
- SSH project collaboration on Linux, macOS and Windows using a matching
  standalone companion; SFTP file transfer.
- Claude Warm Light default theme, native vertical tabs and consistent settings.
- The owner's new black, rimless application icon across macOS and Windows.
- Unified Warpai application identity and `~/.config/.warpai` storage
  (`%USERPROFILE%\.config\.warpai` on Windows), with legacy settings import.

## Downloads

- **macOS Apple silicon:** Warpai.dmg or Warpai.app.zip; move Warpai.app into Applications.
- **Windows x64:** WarpaiSetup-x64.exe, or extract Warpai-windows-x64.zip and launch Warpai.exe.
- **SSH hosts:** choose the Warpai-companion ZIP matching the host's Rust target.
  Extract it on the remote account; Unix binaries need execute permission.

All desktop and companion assets are built from this tag. Companion manifests
include the exact source revision, target and binary checksum; release checksum
files cover the downloadable archives and installers. Companion protocol/package
versions are independent of the desktop product version.

macOS uses ad-hoc signing, not notarization. After checking the source, approve
first launch in System Settings > Privacy & Security if required. Windows may
request approval for an unsigned installer.

## Agent setup

Install and authenticate your CLI agents independently. Enable **Settings >
Features > Agent communication**, select participating agents and start fresh
sessions in the project. Codex must support `-c` and `--no-daemon`; package-manager
updates and the original command remain intact. Unsupported versions run normally
with a visible MCP warning.
