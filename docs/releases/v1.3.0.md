# Warpai 1.3.0

Warpai 1.3.0 pairs the desktop app with Companion 3.0.0 for a self-contained
remote project workflow. These notes summarize changes from the v1.2.0 source
baseline through 1.3.0, including the intervening 1.2.1 and 1.2.2 iterations.

## Changes from 1.2.0 to 1.3.0

### Self-contained Companion 3.0.0

- Remote installers now include a private Git runtime for Code Review. Warpai's
  file tools, Agent coordination, MCP bridge and PTY support run in the compiled
  Companion; text and Markdown previews render in the desktop app.
- Warpai's infrastructure does not require separately installing Git, Python,
  Node, tmux or socat. Vendor Agent CLIs retain their own runtime requirements
  and authentication; SSH/SFTP and the system shell remain prerequisites.
- Linux bundles statically linked Git. macOS Git uses OS libraries only.
  Windows includes MinGit and its DLLs, with the Companion CRT linked statically.
- Git artifacts are pinned and checksum-verified. Installers carry Git license
  notices and source provenance; Unix packages include the matching Git source.
- Runtime files are staged and verified before activation. Reinstallation keeps
  the stable per-account location without changing PATH, shell profiles or SSH
  configuration. The installed executable supports `--check-runtime`.
- Companion keeps its existing on-demand behavior: Warpai starts it when needed,
  and it exits after 60 idle seconds once connections and active Agents end.
  No GUI, system tray or boot service is added.

### Original Review and remote Code View

- Restore the original Code Review toolbar entry and SSH Review after their
  removal in the intervening 1.2.2 baseline correction.
- Explorer and Review share the same connection for the precise SSH session and
  project, using the terminal's confirmed working directory and existing session
  shell integration. No separate Review connection configuration is needed.
- Refresh remote changes when terminal repository metadata updates, and route
  the file-sidebar action to the active remote Review view.
- Open reviewed files in the existing Code View with their original SSH identity.
  Remote edits save to the original file through the existing SFTP path.
- Remote Review remains read-only; use the SSH terminal for staging, commits,
  push and other Git writes. Existing remote Explorer and previews are retained.

### Versioned delivery and documentation

- Desktop installer names include App 1.3.0; remote installer names include the
  independent Companion 3.0.0 version. Protocol major remains 1.
- Updated bilingual product/download information and remote installation guidance
  describe the paired versions and the self-contained runtime.
- Release automation verifies source-matched packages before publishing the
  complete macOS, Windows and three-platform Companion release.

## Downloads and upgrading

- macOS Apple silicon: `Warpai-1.3.0-macos-arm64.dmg`.
- Windows x64: `WarpaiSetup-1.3.0-windows-x64.exe`.
- Remote Linux x64: `WarpaiCompanion-3.0.0-linux-x64.run`.
- Remote macOS Apple silicon: `WarpaiCompanion-3.0.0-macos-arm64.dmg`.
- Remote Windows x64: `WarpaiCompanion-3.0.0-windows-x64-setup.exe`.

Update both the desktop app and Companion under the account used for SSH.
SHA-256 files accompany all five installers. macOS is ad-hoc signed; Windows
installers are unsigned. Existing system approval steps still apply.

## Verification

Before the version bump, three-platform Companion installation/runtime checks
passed, including private Git status/diff with system Git absent from PATH.
Both desktop targets passed default/platform builds, application tests and native
UI assertions, including SSH Review and Review-to-Code-View opening. Their
170-image capture inventories were verified after correcting the workflow count.
Formal release jobs build the immutable v1.3.0 source and check package versions,
native installation and checksums before public delivery.
